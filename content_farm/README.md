# Telegram Video Clipper

YouTube, видео Telegram (до 20 МБ) и видеофайлы из настроенной папки Google Диска.
До трёх вертикальных роликов 1080×1920, 15–60 секунд, с подсветкой слов и оригинальной
речью. Модели сохранены: **Whisper base** и **gemini-3.5-flash**.

## Запуск

```bash
cd /root/tg-video-clipper
python3 -m venv venv
venv/bin/pip install --index-url https://download.pytorch.org/whl/cpu 'torch>=2.3,<3'
venv/bin/pip install -r requirements.txt
cp .env.example .env  # только при первой установке; заполнить ключи
venv/bin/python bot.py
```

Нужны ffmpeg/ffprobe с libass, Node.js >=22 (JS-проверки YouTube) и кириллический шрифт DejaVu Sans. Whisper base
скачивается в `.cache/whisper`. Речь распознаётся частями по 10 минут с перекрытием
и сохранением промежуточных результатов, чтобы длинные исходники не переполняли
память. FFmpeg использует два потока; одновременно
обрабатывается одно видео, остальные стоят в очереди. Для более мощного сервера
настройте ресурсы сервиса и FFMPEG_THREADS. Одна активная задача на пользователя.

Автозапуск:

```bash
cp tg-video-clipper.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now tg-video-clipper
journalctl -u tg-video-clipper -n 50 --no-pager
```

## Личный Google Диск

Обычная папка, расшаренная сервисному аккаунту, не предоставляет ему квоту
хранилища. Для личного Диска нужен OAuth владельца.

1. В Google Cloud Console выберите проект с включённым Google Drive API.
2. Настройте Google Auth Platform: Branding, Audience (External), Data Access
   с `https://www.googleapis.com/auth/drive`. Если приложение в Testing,
   добавьте свой аккаунт в Test users. У тестовых внешних приложений с Drive
   разрешениями refresh token обычно истекает через 7 дней; для постоянной
   работы настройте Production и выполните требования Google для выбранной аудитории.
3. Создайте OAuth client типа **Desktop app**, скачайте JSON и разместите его
   на сервере как `/root/tg-video-clipper/oauth_client.json`, права 600.
4. В `.env` оставьте ID существующей папки `TG_Clipper`.
5. Выполните `venv/bin/python setup_drive.py --auth-url` и откройте выданную
   ссылку на своём компьютере. Войдите владельцем Диска и подтвердите доступ.
6. Скопируйте полный адрес `http://localhost:8765/?...` из адресной строки,
   даже если браузер сообщает, что страница не открывается.
7. Выполните `venv/bin/python setup_drive.py --complete` и вставьте адрес
   в закрытый запрос ввода. Токены сохранятся в `drive_token.json` с правами 600.
8. Проверка: `venv/bin/python setup_drive.py --check`. Перезапуск бота не нужен:
   каждое сохранение использует актуальную авторизацию.

Бот не создаёт публичных разрешений. Видео сохраняются в
`TG_Clipper/user_<telegram_id>/<job_id>/`: исходник, результаты, таймкоды,
транскрипт и субтитры. Ссылки наследуют права папки, они не становятся общедоступными
автоматически. Пользователи получают свои ролики в Telegram; для просмотра на
личном Диске другому аккаунту владелец должен предоставить доступ.

Для Workspace Shared Drive можно использовать `service_account.json`:
добавьте сервисный аккаунт участником общего диска с правом создания файлов,
а GDRIVE_FOLDER_ID направьте на папку общего диска. OAuth не нужен.

Документация: https://developers.google.com/workspace/drive/api/guides/about-shareddrives
и https://developers.google.com/identity/protocols/oauth2/native-app

## Сохранность и восстановление

У каждого задания отдельный каталог `jobs/<id>` и постоянный state.json.
После перезапуска бот возобновляет прерванные и ожидающие задания. Если Google
Диск или Telegram недоступен, файлы остаются на сервере, команда `/retry ID`
повторяет сохранение и доставку. Удаление локального видео происходит только
после подтверждённой архивации, доставки всех роликов и регистрации в ShortPost,
если интеграция включена. Повторная загрузка
использует уже созданные файлы, чтобы не плодить дубликаты.

Команды: `/start`, `/status`, `/files`, `/retry ID`.
Исходник ограничен 2 ГБ и двумя часами; очередью управляет MAX_QUEUE_SIZE.
У бота публичный доступ, каждый видит только свои задания и результаты.
Для исходников Drive поддерживается только настроенная папка и её подкаталоги.
Тот, кто знает ссылку на видео в этой папке, может передать её боту: не размещайте
там файлы, которые не предназначены для такой обработки.

Качество выбора зависит от исходной речи и сохранённых моделей. Нет речи — нет
нарезки. Нет подходящих завершённых моментов — бот сообщает ошибку вместо
случайных обрезков.

По умолчанию VIDEO_LAYOUT=split: основное видео сверху, JackCraft снизу,
субтитры у нижней границы основной части. Фон BG_VIDEO=assets/jackcraft_bg.mp4
собран из двух беззвучных записанных раундов (138 и 162 м), его оригинал сохранён
на Google Диске в JackCraft/preview. Итоговый формат — 1080×1920, 60 кадров/с.
Игра вписывается целиком в нижнюю половину; баннер и счётчики не обрезаются.

Каждый ролик использует свой участок записи, одинаковый при повторе задания.
Если фоновый файл короче основного фрагмента, игра повторяется. Обе части
обрезаются по длительности основного фрагмента и заканчиваются при его окончании:
игрового хвоста после основной части нет. Звук берётся только из исходного видео.
Если игровой фон отсутствует, бот сообщает ошибку. VIDEO_LAYOUT=portrait позволяет
вернуться к вертикальной композиции без игры.


## Постоянные ID и передача в ShortPost

Готовый файл получает имя `CF-<32 символа SHA-256>.mp4`. Этот же код служит
паспортом в ShortPost. Полный SHA-256 хранится в manifest.json и на сервере:
одинаковые файлы повторно не регистрируются. Это проверка совпадения содержимого
файлов; она не определяет похожие сюжеты или разные перекодировки одного видео.
Старые задания с `short_01.mp4` переводятся на новые имена с сохранением Drive ID
и отметок доставки; переименование не отправляет видео повторно в Telegram.

Для интеграции включите `AUTOPOST_ENABLED=true`, задайте HTTPS `AUTOPOST_API_URL`,
ID существующих категории и формата в `AUTOPOST_CATEGORY_ID`/`AUTOPOST_FORMAT_ID`.
В приватном `autopost_credentials.json` разместите объект с полем `farm_token`.
Этот файл находится только на сервере и не передаётся в Worker или Git.
После архивации ферма регистрирует ролики, сервер проверяет доступ и SHA-256
файла на Диске и переводит карточки в `ready`. Запросы регистрации сохраняют
ключи повторов, поэтому потерянный ответ не создаёт вторую карточку.

Временные ошибки Gemini 429/500/502/503/504 сохраняют исходник и расшифровку.
Бот повторяет задание через 1, 3, 10, 30 и 60 минут; после исчерпания повторов
доступна команда `/retry ID`. Выбор модели и распознавание речи не меняются.
Само появление карточки `ready` не публикует ролик: публикацией управляют
расписание, привязанный аккаунт и настроенный Windows Worker.

## Автоматические проверки

`venv/bin/python -m unittest discover -s tests -v` — границы моментов, URL,
субтитры, изоляция пользователей, сохранность и возобновление заданий.
Для реальной проверки необходимы действующие ключи моделей и авторизация Диска.

## Оформление субтитров

`captions.py` создаёт одно событие ASS на целую фразу (обычно 1–3 слова).
Фраза остаётся видимой в коротких промежутках речи, встроенное караоке меняет
только цвет слов. Следующая фраза заменяет предыдущую без наложения и пустого
кадра. При настоящей паузе текст скрывается. Положение закреплено над границей
с JackCraft; для portrait сохраняется нижняя область основного видео.

Ширина рассчитывается по шрифту DejaVu Sans Bold через Pillow, размер и явные
переносы задаются до отрисовки. Автоматический перенос libass отключён. Модели
распознавания и выбора моментов и их параметры не изменяются.

Баннер JackCraft с Telegram-ссылкой расположен в верхнем левом углу игры,
в стороне от кнопок площадок справа. Счётчики перенесены правее баннера.
Нижний якорь субтитров в split-компоновке — y=934 (на 2 px ниже предыдущего).

## Автоматический подбор исходников

Панель → **Загрузка → Подбор исходников · ИИ**. Тематика определяется по ранее
добавленным YouTube-видео. Раз в 6 часов сервис ищет похожие длинные видео,
проверяет метаданные YouTube и предлагает до 8 исходников. Интервал можно
изменить на 12/24 часа, уточнить тематику, поставить подбор на паузу или запустить
вручную. На проверке остаётся максимум 24 предложения; решения не принимаются
по таймеру. Новые предложения не рассылаются отдельными сообщениями бота.

**Взять в работу** сохраняет решение и ровно одно задание анализа в существующей
очереди. После анализа пользователь выбирает количество нарезок; готовые ролики
проходят отдельную модерацию. **Не брать** исключает исходник из следующих
подборок. Комментарии сохраняются отдельно и вместе с последними решениями и
оценками нарезок передаются ИИ при следующем поиске. Это контекст для модели,
а не обучение её весов. Предварительный подбор использует метаданные, а не
полный просмотр или скачивание видео.

Сервис работает на сервере отдельно от бота и Windows. Использует уже
настроенные `GEMINI_API_KEY`, `AUTOPOST_API_URL`, `AUTOPOST_TOKEN_FILE` и ту же
модель из `config.py`; дополнительных ключей YouTube не нужно.

Для установки на существующий сервер скопируйте `discovery.py` в каталог фермы
и установите `deploy/shortpost-source-discovery.service` в systemd. В шаблоне
указан существующий путь `/root/tg-video-clipper`; на другом сервере измените
`WorkingDirectory` и `ExecStart`. Выполните `systemctl daemon-reload`, затем
`systemctl enable --now shortpost-source-discovery`. Для разовой проверки —
`venv/bin/python discovery.py --once`. API сервера должен быть обновлён вместе
с модулем `app/discovery.py`. Результаты и решения хранятся в PostgreSQL;
`.discovery-result.json` — приватная квитанция для повторной доставки результата
после сбоя сети. Ошибки поиска/ИИ видны в панели, повтор — через 30 минут.
