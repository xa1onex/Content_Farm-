# Управление самой Windows

Отдельный канал позволяет оператору выполнять команды Windows, читать результаты и настраивать сеть эмуляторов. Это административный доступ к ПК под пользователем, указанным в пакете подключения. Публикация роликов остаётся отдельной операцией Worker.

## Подключение

Предпочтительный запуск: скачайте подготовленный `CONNECT-WINDOWS.cmd` и откройте его на ПК с MuMu. Он сам скачивает архив с закреплённой версией установщика, сверяет SHA256, распаковывает его в `%LOCALAPPDATA%\ShortPost\windows-control-installer-v2` и запускает настройку. Запрос администратора выполняется самим установщиком; пароль другой учётной записи вводить не нужно. При наличии установленного Worker этапы и ошибки отправляются оператору автоматически с прежним токеном Worker. Токен остаётся на ПК и не попадает в журнал или пакет.

Ручной запуск пакета также поддерживается:

1. Получите подготовленный для вашего ПК ZIP-пакет от оператора. В нём находятся `connect-windows.cmd`, `connect-windows.ps1`, `disconnect-windows.cmd`, `report-windows-control.py`, `connection.json`. Приватных ключей в пакете нет.
2. Распакуйте ZIP полностью. Запустите `connect-windows.cmd` двойным щелчком под тем же пользователем Windows, что использует Worker. Подтвердите запрос администратора Windows, не переключаясь на другую учётную запись.
3. Дождитесь строки `Connecting Windows control`. При необходимости Windows сначала установит собственный компонент OpenSSH Server; установка может занять несколько минут.
4. Оставьте появившееся окно открытым. После обрыва сети подключение повторяется автоматически. Оператор сам проверяет вход и получает сетевой отчёт.

При ошибке окно остаётся открытым, статус сохраняется в `%LOCALAPPDATA%\ShortPost\windows-control-bootstrap\latest.json`, а журналы — в `connect-PID.log` того же каталога. В heartbeat сервера передаётся только короткий статус/сообщение установщика, без журналов, файлов конфигурации, токенов или окружения процесса. Отправка не создаёт заданий и не запускает публикации. Если Worker ещё не установлен, путь проекта отличается или сервер недоступен, журнал сохраняется локально. Эта отправка не заменяет проверку настоящего входа в Windows.

Windows SSH слушает только `127.0.0.1` на отдельном порту. Исходящее SSH-подключение связывает его с loopback-портом сервера; порты ПК в интернет не открываются. Вход разрешён только указанному Windows-пользователю и по отдельному публичному ключу оператора. Пароли отключены. Ключ сервера закреплён в пакете. Текущий канал Appium используется независимо.

На сервере отдельный пользователь может открыть только разрешённый обратный порт. Он не получает shell и не меняет политику root или существующего пользователя Appium. Приватный ключ для входа в Windows остаётся у оператора. Уже созданный на ПК ключ `shortpost-appium` используется для исходящего туннеля и не покидает ПК.

Если обнаружена прежняя конфигурация Windows SSH или занятый порт, установщик останавливается до изменений. Прежний SSH не перезаписывается автоматически. Если установка нового канала завершилась ошибкой после изменений, она пытается восстановить прежнее состояние. Параметры доступа находятся в `connection.json`; публиковать приватные ключи или заменять этот файл непроверенным пакетом нельзя.

## Отключение

Закройте окно подключения или нажмите Ctrl+C: сервер потеряет канал к ПК. Для полного отключения и восстановления состояния службы запустите `disconnect-windows.cmd` и подтвердите запрос администратора. Сначала закройте окно переподключения. Если конфигурация SSH была изменена вручную после установки, автоматическое восстановление останавливается для проверки оператором.

Служба не добавляется в автозапуск: используется ручной запуск, и после перезагрузки ПК нужно снова открыть `connect-windows.cmd`. Установленный компонент Microsoft OpenSSH остаётся на ПК; отключение канала не удаляет системный компонент. Глобальная политика выполнения PowerShell, основная сеть Windows, настройки MuMu и аккаунтов не меняются.

## Что ещё требует проверки на настоящем ПК

Проверка синтаксиса и защитных веток установщика не подтверждает установку компонента, работу SSH-службы, вход по ключу или административные права в удалённой сессии. После запуска пакета оператор обязан проверить пользователя/ПК и права, затем получить сетевой отчёт, прежде чем менять сеть. Рабочим доступ считается только после успешной команды через новый канал.
