# Платформенные адаптеры и профили

Реализации `platforms/tiktok.py`, `instagram.py`, `youtube.py` используют общий PlatformPublisher. Это исполняемая логика с versioned configuration, а не обещание универсальных селекторов для любой версии приложения. На доступном Linux-хосте реальные приложения не проверялись. Bundled profiles — **draft examples**, navigation_verified=false. Без локально проверенного профиля live preflight откажется запускаться.

## Калибровка на одном эмуляторе

1. Скопируйте PLATFORM.example.json в PLATFORM.local.json, укажите его в `[devices.profiles]`. Узнайте точный Android package, app_version (`adb shell dumpsys package PACKAGE`) и locale. Пакеты в примерах ориентировочные; выберите фактически установленный вариант.
2. При остановленном Worker запустите `inspect-ui --external-id mumu-01` или `record-locator --external-id mumu-01 --output selector.local.json`. Запись locator **ничего не нажимает**.
3. Заполните account_steps и account locator, который возвращает настоящий handle, не display name. Адаптер сравнивает его с assignment.account.username. UI ambiguous/missing → остановка.
4. Запишите upload_steps: native create/upload/picker и точный файл `{filename}`. Worker помещает видео в отдельную папку `/sdcard/Movies/ShortPost/<job_uuid>/<job_uuid>.mp4`. Если приложение скрывает имена файлов, выберите альбом `{media_album}` (UUID задания) и единственную миниатюру внутри него. Несколько совпадений останавливают навигацию. metadata_steps используют source=caption/title/filename/media_album. Для picker не используйте случайный первый thumbnail из общих «Недавних».
5. submit — отдельный финальный selector. Его нельзя повторно включить как click в account/upload/metadata/verification/metrics/parameter flows; валидация профиля это запрещает. Для известного диалога, который появляется не всегда, можно задать click с `optional=true` и коротким `timeout_seconds`. Например, «Начать новое видео» в диалоге старого черновика. Пропускается только отсутствие этого элемента; неоднозначный selector, потеря соединения, истечение аренды и ошибки платформы останавливают работу. Выбор аккаунта, файла и проверка результата остаются обязательными.
6. confirmation и verification_steps должны приводить к **именно новому** опубликованному ролику. caption_proof/author_proof проверяют содержимое и аккаунт. Для YouTube проверяется title; для TikTok/Instagram caption. published_url возвращает настоящую ссылку; альтернативно url_source=clipboard после контролируемого Copy link. Старый известный URL/clipboard запрещён как доказательство новой публикации.
7. errors содержит известные селекторы captcha/platform_block/login_required. Появление этих элементов вызывает остановку и код операторского вмешательства. Неизвестный UI не нажимается наугад.
8. max_duration_seconds, max_caption_chars и max_title_chars задаются под реально проверенную версию/тип публикации. Worker не угадывает меняющиеся лимиты приложений.

JSON schema: `profiles/schema.json`. Все параметры профиля типизированы, неизвестные поля отвергаются.

## Безопасная навигация — уровень B

```powershell
.\.venv-worker\Scripts\shortpost-worker.exe test-navigation --external-id mumu-01 --platform tiktok --username ACTUAL_HANDLE --video C:\Private\test.mp4
```

Команда не claim-ит задания, не отправляет result/statistics и не вызывает submit. Она проверяет реальный аккаунт, staging, upload/metadata flow, находит финальную кнопку и останавливается. Только успешный проход записывает navigation_verified=true. Останется проверить подтверждение/URL на реальной согласованной публикации уровня C; это не считается пройденным от одного navigation test.

Для Instagram 452.0.0.0.43 на русском добавлен профиль `instagram-452.0.0.0.43-ru-RU.navigation.json`. Он предназначен только для проверки подготовки ролика: `navigation_only=true` запрещает Submit и live-запуск даже после успешной навигации. Непроверенные селекторы подтверждения публикации в него не включены. Версия, язык и настоящий аккаунт проверяются перед выбором файла. Запуск на Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-instagram-navigation.ps1 -Username YOUR_HANDLE -Video C:\Private\test.mp4
```

Скрипт создаёт локальную копию профиля, сохраняет существующую копию при повторном запуске и вызывает обычную команду Worker. Параметр `test-navigation --profile PATH` выбирает профиль только для диагностики и не меняет привязку устройства в TOML. Для другой версии или языка этот профиль останавливается до загрузки видео; нужна повторная калибровка.

После успешного прохода скрипт отправляет через `--report-server` обычный Worker heartbeat с `capabilities.navigation_test`: платформа ПК, аккаунт, версия и язык приложения, SHA-256 входного видео, время и признак остановки до Publish. Токен читается из DPAPI; изображения, содержимое видео, пути файлов и секреты в отчёт не попадают. Claim, result и статистика публикаций не вызываются. Это временный отчёт последнего heartbeat, не запись об опубликованном ролике. При запуске `test-navigation` напрямую отчёт отправляется только с явным `--report-server`.

Если оператор уже подготовил диагностический файл в отдельном альбоме MuMu, вместо `-Video` можно передать `-StagedVideo /sdcard/Movies/ShortPost/JOB_UUID/JOB_UUID.mp4 -ExpectedSha256 EXPECTED_SHA256`. Скрипт копирует только указанный файл через SDK ADB с loopback-устройства, проверяет SHA-256, запускает тот же Windows Worker и удаляет свою временную копию. Другие каталоги Android этим режимом не принимаются. Адрес для экземпляра №0 по умолчанию — `127.0.0.1:16384`; другой подтверждённый адрес задаётся через `-AdbEndpoint`.

## Параметры публикации

Публичные подписи и заголовки содержат только описание контента. Служебные
паспорта роликов, UUID заданий, SHA-256 и имена файлов не добавляются в подпись,
заголовок или кадр. Для учёта и защиты от повторов используются внутренние
метаданные и настоящая ссылка публикации, а не видимый зрителям ID.

- TikTok: caption, visibility public/friends/private, allow_comments boolean.
- Instagram: caption, allow_comments boolean.
- YouTube: title, caption/description, **обязательные** visibility public/unlisted/private и made_for_kids boolean.

Неизвестный параметр отклоняется. Для опций кроме текста profile.parameter_steps должен содержать UI flow именно для требуемого значения, например visibility.private и made_for_kids.false. Нельзя молча использовать предыдущее UI-значение. default_parameters — явные настройки владельца профиля; job.parameters имеют приоритет. YouTube example использует private и not-made-for-kids только как пример конфигурации; владелец обязан выбрать верную аудиторию собственного контента.

## Подтверждение и аналитика

Профиль `instagram-452.0.0.0.43-ru-RU.reels.json` использует отдельную проверку Reels для этой версии и языка. До загрузки считываются точное число публикаций и ссылка последнего собственного ролика. После Submit Worker ждёт увеличения числа ровно на один, проверяет автора и полное описание открытого ролика и получает новую ссылку через Copy link. Буфер обмена предварительно очищается служебным маркером: старое значение не считается успешным копированием. Изменение числа более чем на один, старый URL, потеря аренды или тайм-аут дают неопределённый результат без повторного Submit. Пустой аккаунт допускается с исходным числом 0; сокращённое число вроде «1 тыс.» не принимается. Профиль пока имеет `navigation_verified=false`: до проверки настоящего UI live-запуск запрещён.

Для согласованной проверки одного задания предусмотрен `run-once --job-id UUID --external-id mumu-01 --profile PATH --live`. Серверный claim с `job_id` сохраняет все обычные проверки владельца, устройства, окна и статуса аккаунта; при недоступности указанного задания другое не выдаётся. Команда использует обычный Engine: ACK, билет, проверка SHA-256, ADB, продление аренды, единственный Submit и result. Затем процесс завершается. Постоянный `allow_publish` и TOML не меняются. Локальная пауза и неразобранные задания блокируют запуск; завершённая локальная публикация повторно не исполняется. Обёртка Windows — `scripts/run-one-job.ps1 -JobId UUID`. Это реальная публикация, требующая разрешения владельца; включать её до калибровки профиля нельзя.

Успех — не факт нажатия. Нужны confirmation, proof автора/текста и настоящий platform URL. TikTok извлекает numeric video ID и сверяет handle в URL; Instagram — Reel shortcode; YouTube — настоящий 11-символьный video ID. Случайный UUID не принимается. Неоднозначный результат после Submit — unknown, новая попытка Submit запрещена.

`confirmation_timeout_seconds` задаёт ожидание confirmation: по умолчанию 30 секунд, максимум 1800. Для медленной загрузки Instagram настройте его по результатам проверки на ПК. Во время ожидания Worker продолжает продлевать аренду задания и проверяет её перед каждым опросом UI; общий `max_processing_seconds` также ограничивает работу. Истечение времени или потеря аренды после Submit дают unknown, повторного нажатия не происходит. Исчезновение полосы загрузки само по себе не доказывает публикацию: по-прежнему нужны автор, текст и ссылка нового ролика.

metrics_steps возвращаются к конкретному URL, metric_post_proof проверяет внешний ID. Доступные selectors метрик читают точные целые значения; сокращённые/неоднозначные `1.2K`, `1,2 тыс.` не превращаются в придуманные числа. Retention принимается как видимый точный процент; недоступные значения не отправляются. Без настроенных metrics selectors Worker сообщает metrics_unavailable и повторяет измерение позже, не отправляя нули.

Изменение версии/языка приложения требует повторной калибровки. Не редактируйте профили на ходу при активной публикации. Все три платформы остаются **не принятыми на настоящем приложении** до раздельных тестов C с разрешения владельца.
