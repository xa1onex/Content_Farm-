# Подготовка приложений на эмуляторах

Worker устанавливает недостающие приложения через официальный Google Play:

| Приложение | Android package |
|---|---|
| YouTube | `com.google.android.youtube` |
| TikTok | `com.zhiliaoapp.musically` |
| Google Drive | `com.google.android.apps.docs` |
| Instagram | `com.instagram.android` |
| ProxySocket | `com.deniyitunji.proxysocket` |

Источник ProxySocket выбран владельцем проекта: https://play.google.com/store/apps/details?id=com.deniyitunji.proxysocket . Остальные записи также закреплены по package ID официальных карточек Google Play, а не поиску по похожему названию.

## Использование

Вход в Google Play выполняется владельцем вручную на каждом эмуляторе. В MuMu должны работать Google Play Services и сам магазин. Эмулятор должен быть привязан через `bind`; `--all` означает все включённые устройства в `config.local.toml`, а не все произвольные экземпляры в MuMu Manager.

```powershell
.\.venv-worker\Scripts\shortpost-worker.exe provision-apps --all
```

Проверка без установки:

```powershell
.\.venv-worker\Scripts\shortpost-worker.exe provision-apps --all --check-only
```

Один эмулятор:

```powershell
.\.venv-worker\Scripts\shortpost-worker.exe provision-apps --external-id mumu-01
```

При обычном запуске `run` проверка и установка включены по умолчанию (`auto_install_apps = true`). Сначала выполняется восстановление старых заданий; затем при отсутствии незавершённых попыток идёт подготовка приложений. Во время подготовки работают серверные heartbeat, новые задания ещё не запрашиваются, сбор аналитики начинается после подготовки. Неполная подготовка завершает запуск с `required_apps_not_ready`.

Для запуска только восстановления/соединения без подготовки можно явно задать в верхней части TOML:

```toml
auto_install_apps = false
```

Установка запрещена при незавершённых/неопределённых публикациях и при занятом lock Worker. Не удаляйте journal для обхода этой проверки.

## Поведение

- Уже установленные пакеты пропускаются. Автоматического обновления, переустановки и удаления данных нет; версия социальных приложений влияет на проверенные профили публикации.
- Для отсутствующего приложения открывается точная карточка Google Play. Установщик проверяет активный пакет магазина, название приложения и единственную кнопку `Установить` / `Install`.
- Предложение Google Play Pass отклоняется только через единственную кнопку `Не сейчас` / `Not now` / `No thanks`. Платные предложения не принимаются.
- После одного нажатия ожидается подтверждение наличия Android package. Одна лишь кнопка или факт нажатия не считаются успехом.
- CAPTCHA, вход, подтверждение личности, региональная недоступность и неизвестный интерфейс остаются явными ошибками. APK из сторонних источников не скачиваются.
- Устройства обрабатываются последовательно, перед каждым проверяется свободная RAM/диск. Запущенные экземпляры остаются открытыми; при нехватке ресурсов отчёт покажет `insufficient_resources`.
- Отдельный код результата для каждого приложения сохраняется в `%LOCALAPPDATA%\ShortPost\provisioning\latest.json`. CLI возвращает код 2, если хотя бы одно устройство не готово. Секреты Google и прокси в отчёт не входят.
- Установка не выполняет вход в социальные аккаунты и не включает VPN/прокси. Настройка ProxySocket и разрешение VPN — отдельный этап.

`play_install_timeout_seconds` задаёт ожидание одного приложения, по умолчанию 600 секунд. Проверенные локализованные подписи кнопок — русский/английский; неизвестный UI останавливает попытку.

## Проверка

Модульные тесты проверяют повторный запуск, точные package ID, отсутствие кликов в check-only, отказ при неоднозначной кнопке/чужой карточке, вход/недоступность/проверку личности, тайм-аут без повторных кликов, отклонение Play Pass, блокировку при незавершённой публикации, остановку и продолжение обработки следующего устройства после ошибки.

Реальная проверка на конкретном MuMu фиксируется отдельно; она не означает готовность всех остальных экземпляров или вход в их аккаунты.
