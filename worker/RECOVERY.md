# Журнал, восстановление и ошибки

SQLite journal расположен в `%LOCALAPPDATA%\ShortPost\journal.sqlite3`, режим WAL, synchronous=FULL. Не удаляйте базу, WAL/SHM или token.dpapi для «сброса ошибки»: это уничтожит сведения о потенциально опубликованном ролике. SQLite schema v1 контролируется PRAGMA user_version; новая неподдерживаемая версия не пересоздаётся автоматически.

Assignment, lease, request payload, response и result зашифрованы user-scoped Windows DPAPI. Idempotency-Key/event ID создаются до запроса. Перед финальным кликом irreversible_at фиксируется отдельной транзакцией. Если commit неуспешен, нажатие не выполняется. Клиент Appium не повторяет HTTP click автоматически.

| Момент сбоя | Поведение |
|---|---|
| Ответ claim потерян | Повтор того же ключа, атомарное сохранение assignment вместе с response |
| До ACK | Внешних действий нет; сервер может безопасно вернуть lease в очередь |
| ACK был, Submit ещё не начинался | После рестарта UI не повторяется; возможен explicit safe_failure, если сервер ещё processing |
| После irreversible marker | Только восстановление результата/unknown; Submit повторно не вызывается |
| Published result сохранён, ответ потерян | Отправляется прежний payload/event/key; publication_id и задачи аналитики восстанавливаются |
| Lease/авторизация потеряны | Guard прекращает новые UI-действия; уже возможный внешний эффект → unknown |
| Server уже unknown | Не понижать до safe_failure; требуется операторская проверка |

Тот же пост нельзя выполнить повторно ради передачи результата. Result в journal неизменяем; не меняйте unknown на safe_failure вручную. При восстановлении сначала сверяются серверные статусы; подтверждённые terminal/операторские решения снимают локальную блокировку. Unknown останавливает приём новых заданий из-за отсутствия device-filtered claim в текущем контракте.

Оператор должен остановить прежнюю попытку и проверить реальный аккаунт. Затем на сервере resolve_published с настоящим ID/временем либо resolve_not_published с основанием. Только серверное решение разрешает безопасный retry исходного задания. Это не обходится перезапуском ПК или новой локальной SQLite.

CAPTCHA/login/block возвращаются отдельными ошибками. При UIError новые claims автоматически ставятся на паузу; изучите приватные screenshot/XML, исправьте UI/аккаунт/профиль и используйте resume после сверки с сервером. Ни пароли, ни bearer/lease/ticket в JSON-логи не попадают.

Graceful stop: CLI stop → прекращение claims → завершение текущих операций с renew → закрытие sessions/client. При жёстком выключении Windows журнал переживает рестарт. Задачи метрик имеют постоянную пару publication_id/hours; при потере ответа сначала повторяется существующий snapshot outbox, а не новое измерение с прежним event ID.

API не гарантирует транзакцию между PostgreSQL и внешней соцсетью. Консервативный unknown — намеренный результат при недостатке доказательств, а не повод для автоматической перепубликации.
